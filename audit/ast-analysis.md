# AI Java Reviewer — AST Validation Audit

This document audits the AST representation and validation mappings generated by the parsers.

## 🌳 AST Model Structure

The parsed Java files are represented as instances of `IJavaClass` conforming to the interface defined in `src/models/index.ts`:

```typescript
export interface IJavaClass {
  readonly filePath: string;
  readonly packageName: string;
  readonly className: string;
  readonly fullyQualifiedName: string;
  readonly classType: ClassType; // 'class' | 'interface' | 'enum' | 'record'
  readonly stereotype: SpringStereotype; // 'Service' | 'Controller' | 'Repository' etc.
  readonly annotations: string[];
  readonly fields: IJavaField[];
  readonly methods: IJavaMethod[];
  readonly imports: string[];
  readonly superClass?: string;
  readonly interfaces: string[];
  readonly lineCount: number;
  readonly rawContent: string;
}
```

## 🐞 Identified AST Mapping Issues

1. **Primitive vs Reference Types**:
   In `JavaAstParser.extractTypeString()`, reference types extraction is heavily nested:
   ```typescript
   const refNode = unannTypeNode.children?.referenceType?.[0] || unannTypeNode.children?.unannReferenceType?.[0];
   ```
   If a reference type contains generics (e.g. `List<User>`), it returns the raw type name (`List`) but discards the generic parameter (`User`), which limits rules checking for generic entity exposure.

2. **Method Body End Offsets**:
   In `JavaAstParser.parseMethod()`, the method body extraction is done via:
   ```typescript
   const body = methodNode.children.methodBody?.[0] && methodNode.location 
     ? rawContent.substring(methodNode.location.startOffset, methodNode.location.endOffset + 1) 
     : '';
   ```
   If a method has comments or multiple inner block statements, `java-parser` offsets might sometimes misalign, yielding truncated or incorrect body bounds.

3. **Field Declarations with Multiple Variables**:
   For declarations like `private String a, b;`, the parser splits them into separate `IJavaField` entities but assigns the same `rawSource` which might cause regex-based rules to trigger multiple findings on the same line.
