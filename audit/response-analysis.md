# AI Java Reviewer — Response Quality & Formatting Audit

This document evaluates the final review reports generated by the extension.

## 📝 Generated Markdown Report Layout

The final report generated in `.review-ai/reports/review-[timestamp].md` is formatted in `ReportFormatter.ts` using:
1. **Title**: `# 🛡️ Enterprise AI Java Review Report`
2. **Executive Summary & Health Matrix**: Tabular overview of scores and file counts.
3. **Technical Debt by Module**: Summary of estimated remediation time per directory.
4. **Highest Risk Classes**: Top 5 files based on findings count.
5. **Grouped Issue Analysis & Remediation Cards**: Details of each static finding, source code snippet, and unified diff.
6. **AI Architectural Analysis & Recommendations**: Appends the text returned by the LLM.
7. **Prioritized Remediation Roadmap & Sprint Plan**: Remediation phases mapped by severity.

---

## 🐞 Analysis of Quality Issues

1. **Empty / Warning Blocks in AI Recommendations**:
   Because the LLM receives no code context, it returns fallbacks or warnings like "No active VS Code Chat models detected..." or blank recommendations, which are then appended verbatim to the report.
2. **Stale Evidence Snippets**:
   In some cases, the report formatter prints placeholders (e.g. `Object generateStudentReportCsv(...)`) rather than retrieving the actual lines from the source file. This is because the formatter does not extract code from the file system; it relies on the static rule's `codeSnippet` property, which is sometimes populated with simple method headers instead of actual body lines.
3. **No Validation of AI Output**:
   The LLM output is appended raw without any post-processing validation, meaning that if the LLM fails with a JSON error or raw system trace, the trace is written directly into the markdown report.
